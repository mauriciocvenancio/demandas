API de Solicitações

API REST para integração de sistemas externos com o módulo de Solicitações (novo item / melhoria). Permite criar, consultar e atualizar o status de solicitações diretamente via HTTP.

Base URL: https://seudominio.com.br/demandas/api/solicitacoes.php
🔑 Autenticação

Todas as requisições devem enviar o token de acesso no header HTTP:

Header obrigatório
X-Api-Token: SEU_TOKEN_AQUI
⚠️ O token é gerado no banco de dados na tabela api_tokens. Guarde-o em local seguro e nunca o exponha publicamente.

Resposta quando o token é inválido ou ausente

HTTP 401
{ "ok": false, "erro": "Token inválido ou inativo." }

Criar Solicitação
POST /api/solicitacoes.php Cria uma nova solicitação

A solicitação entra automaticamente com status nova e origem api.

Campos do body (JSON)

CampoTipoReq.Descrição
titulostring✅Título da solicitação (máx. 200 chars)
cidadestring✅Cidade do solicitante
nome_solicitantestring✅Nome completo
tipostring—novo_item ou melhoria (padrão: novo_item)
descricaostring—Descrição detalhada
email_solicitantestring—E-mail de contato
telefone_solicitantestring—Telefone de contato
cargo_solicitantestring—Cargo ou função
prioridadestring—Ver tabela de valores (padrão: media)
ref_externastring—ID ou código no sistema externo

Requisição

HTTP Request
POST /demandas/api/solicitacoes.php
X-Api-Token: SEU_TOKEN_AQUI
Content-Type: application/json

{
  "tipo":                 "melhoria",
  "titulo":               "Adicionar campo CPF no cadastro",
  "descricao":            "Precisamos registrar o CPF para emissão de relatórios.",
  "cidade":               "Bituruna",
  "nome_solicitante":     "Maria Souza",
  "email_solicitante":    "maria@bituruna.pr.gov.br",
  "telefone_solicitante": "(42) 99812-3456",
  "cargo_solicitante":    "Assistente Social",
  "prioridade":            "alta",
  "ref_externa":          "TICKET-2024-001"
}

Resposta de sucesso

HTTP 201 — Created
{ "ok": true, "id": 15, "status": "nova" }

Erros possíveis

HTTP 400
{ "ok": false, "erro": "Campo obrigatório: titulo." }
{ "ok": false, "erro": "Body JSON inválido ou vazio." }

Atualizar Status
PATCH /api/solicitacoes.php?id=X Altera o status e registra no histórico

Parâmetros de URL

ParâmetroReq.Descrição
id✅ID da solicitação

Campos do body (JSON)

CampoReq.Descrição
status✅Novo status (ver tabela de valores)
observacao—Comentário sobre a mudança

Requisição

HTTP Request
PATCH /demandas/api/solicitacoes.php?id=15
X-Api-Token: SEU_TOKEN_AQUI
Content-Type: application/json

{
  "status":     "em_analise",
  "observacao": "Iniciando análise de viabilidade técnica."
}

Resposta de sucesso

HTTP 200
{
  "ok":              true,
  "id":              15,
  "status_anterior": "nova",
  "status_novo":     "em_analise"
}

Erros possíveis

HTTP 400 / 404
{ "ok": false, "erro": "Status inválido. Valores aceitos: nova, em_analise, aprovada..." }
{ "ok": false, "erro": "Solicitação não encontrada." }
{ "ok": false, "erro": "Informe ?id= na URL." }
⚠️ Códigos de Resposta HTTP
CódigoSignificado
200 OKRequisição bem-sucedida
201 CreatedSolicitação criada com sucesso
204 No ContentResposta a requisições OPTIONS (CORS preflight)
400 Bad RequestCampo obrigatório ausente, valor inválido ou JSON inválido
401 UnauthorizedToken ausente, inválido ou inativo
404 Not FoundSolicitação não encontrada
405 Method Not AllowedMétodo HTTP não suportado
ℹ️ Todas as respostas de erro seguem o formato: { "ok": false, "erro": "mensagem descritiva" }
🔄 Fluxo de integração
  1. Sistema externo recebe a solicitação do usuário
  2. POST /api/solicitacoes.php → retorna { "id": 15, "status": "nova" }
  3. Salvar o id retornado no sistema externo para consultas futuras
  4. Equipe interna analisa e atualiza status pelo painel web
  5. (Opcional) GET /api/solicitacoes.php?id=15 → consultar status atualizado
  6. (Opcional) PATCH /api/solicitacoes.php?id=15 → atualizar status via API
💻 Exemplos com cURL

Criar solicitação

bash
curl -X POST "https://seudominio.com.br/demandas/api/solicitacoes.php" \
  -H "X-Api-Token: SEU_TOKEN_AQUI" \
  -H "Content-Type: application/json" \
  -d '{
    "tipo": "melhoria",
    "titulo": "Novo relatório de atendimentos",
    "cidade": "Bituruna",
    "nome_solicitante": "Maria Souza",
    "email_solicitante": "maria@municipio.gov.br",
    "prioridade": "alta"
  }'

Consultar detalhe

bash
curl -X GET "https://seudominio.com.br/demandas/api/solicitacoes.php?id=15" \
  -H "X-Api-Token: SEU_TOKEN_AQUI"

Listar todas as cidades com contagens

bash
curl -X GET "https://seudominio.com.br/demandas/api/solicitacoes.php?cidades=1" \
  -H "X-Api-Token: SEU_TOKEN_AQUI"

Listar solicitações de uma cidade

bash
curl -X GET "https://seudominio.com.br/demandas/api/solicitacoes.php?cidade=Bituruna&status=nova" \
  -H "X-Api-Token: SEU_TOKEN_AQUI"

Buscar por referência externa

bash
curl -X GET "https://seudominio.com.br/demandas/api/solicitacoes.php?ref_externa=TICKET-2024-001&cidade=Bituruna" \
  -H "X-Api-Token: SEU_TOKEN_AQUI"

Atualizar status

bash
curl -X PATCH "https://seudominio.com.br/demandas/api/solicitacoes.php?id=15" \
  -H "X-Api-Token: SEU_TOKEN_AQUI" \
  -H "Content-Type: application/json" \
  -d '{"status": "aprovada", "observacao": "Aprovado em reunião de equipe."}'
🛡️ Gerenciamento de Tokens

Os tokens são gerenciados na tabela api_tokens do banco de dados.

⚠️ Nunca compartilhe o token em código-fonte público ou repositórios. Trate-o como uma senha.

Criar novo token

SQL
INSERT INTO api_tokens (nome, token)
VALUES ('Nome do Sistema', SHA2(CONCAT('api_', UUID()), 256));

-- Ver o token gerado:
SELECT nome, token FROM api_tokens ORDER BY id DESC LIMIT 1;

Listar tokens ativos

SQL
SELECT id, nome, LEFT(token, 16) AS token_inicio, criado_em
FROM api_tokens
WHERE ativo = 1;

Desativar um token

SQL
UPDATE api_tokens SET ativo = 0 WHERE id = 1;
